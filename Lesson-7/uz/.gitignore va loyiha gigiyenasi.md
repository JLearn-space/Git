## .gitignore va loyiha gigiyenasi

> **O'tgan dars bilan bog'liqlik:** endi siz jamoada va GitHubda ishlaysiz. Bugun tozalik haqida gapiramiz — repozitoriy qanday tartibda saqlanadi: qaysi fayllar unga hech qachon tushmasligi kerak, loyiha tuzilmasini qanday yaratish va nega `.gitignore` ko'ringanidan muhimroq.

---

## Dars maqsadi

Repozitoriyni toza saqlashni o'rganish: `.gitignore` qoidalarini yozish, loyiha ildizini rasmiylashtirish va — eng muhimi — sir va mashina generatsiya qilgan fayllar oqib chiqishiga yo'l qo'ymaslik.

## Dars oxirida nimani o'rganasiz

- `.gitignore` nima qilishini va nega bu hashamat emasligini tushuntirish.
- `.gitignore` bazaviy patternlarini yozish: izohlar, papkalar, `*`, `**`, inkor `!`.
- `.gitkeep` bilan bo'sh papkalarni versiya nazoratida ushlab turish.
- Loyihaning saranjom ildizini yig'ish: README, LICENSE, papkalar.
- Nega sir va tokenlarni hech qachon commit qilish mumkin emasligini tushunish.

---

## 1-blok. `.gitignore` nima va nega

**Oddiy qilib:** safar oldidan chamadon yig'asiz. Poltagidagi axlatni yoki «har ehtimolga» uchinchi bir xil kurtkani solib bo'lmaydi — hammasini o'zingiz bilan ko'tarish kerak bo'lardi. `.gitignore` — repozitoriy uchun «chamadonga solmaymiz» ro'yxati.

**`.gitignore` — maxsus fayl** (repozitoriy ildizida) Git **e'tiborsiz qoldiradigan** fayl va papkalar uchun qoidalar: kuzatmaydi, `git status`da ko'rsatmaydi, tasodifan commit qilmaydi.

### Bu nima uchun kerak

- **Mashina axlati.** `node_modules` (o'n minglab fayllar), build natijalari, kesh — bular bitta buyruq bilan qayta yaratiladi. Repozitoriyda ular uni shishirib yuboradi.
- **Shaxsiy ma'lumotlar.** Yo'llaringizdagi `config.json`, tokenli `.env`, lokal ma'lumotlar bazasi.
- **OS axlati.** `.DS_Store`, `Thumbs.db`, muharrir fayllari — faqat sizning mashinangizda kerak.

Haqiqiy misollar:

```text
# Kursning o'z fayllari — haqiqiy .gitignore
.DS_Store
.obsidian/
.idea/
.vscode/
*.swp
```

Kurs papkasining ro'yxatini `git status` bilan solishtiring: yashirin fayllar ko'rinmaydi, chunki `.gitignore` ularni ushlab turadi — fayl siz sezmasangiz ham ishlaydi.

---

### Yangi boshlovchilarning ko'p uchraydigan xatolari

| Xato | Qanday tuzatish |
| --- | --- |
| `.gitignore`ni «muammo bo'lguncha» qoldirish | Qoidalarni birinchi kundayoq yozish shishgan repozitoriyni keyinchalik tozalashdan oson |
| Faqat ignore qilish, lekin bitta fayl avval commit qilinganini unutish | `.gitignore` *yangi* fayllarni himoya qiladi; kuzatilayotganlar kuzatiladi — `git rm --cached` kerak |
| `.env` misolini ignore qilib, haqiqiysini commit qilish | Sirlar umuman repozitoriysa qo'shilmaydi; avval ignore qiling |
| Git yengillashadi deb `node_modules`ni diskdan o'chirish | Fayllar birinchi `install`da qaytadi — repozitoriydan o'chiring, diskdan emas |

## 2-blok. Pattern sintaksisi

`.gitignore` — matnli fayl, har bir qator qoida. Haqiqiy ehtiyojlarning 90 foizini qoplaydigan beshta bosh patternni o'zlashtiramiz:

### 1. Izoh — `#` bilan qator

```gitignore
# Node.js bog'liqliklari
node_modules/
```

### 2. Fayl nomi yoki yo'li aniq

```gitignore
secret.txt            # istalgan papkadagi secret.txtni ignore qilish
docs/private/plan.md  # ma'lum papkadagi aniq fayl
```

### 3. Papka — oxirida `/` slash

```gitignore
node_modules/    # butun papkani ignore qilish
build/
```

Slashli papka nomi uni *va ichidagi hammasini* ignore qiladi.

### 4. Yulduzcha `*` — istalgan belgilar

```gitignore
*.log        # barcha .log fayllari
config.*     # config.json, config.yaml, config.yml
```

### 5. Qo'sh yulduzcha `**` — istalgan ichki chuqurlik

```gitignore
**/__pycache__/   # istalgan pastki papkadagi __pycache__
**/tmp            # istalgan chuqurlikdagi tmp fayl yoki papka
```

### Inkor — `!`

`!` qoidasi kengroq qoida bekor qilgan narsani qaytarishi mumkin:

```gitignore
*.log
!important.log     # barcha .log'ni ignore qilish, lekin important.log'ni emas
```

Qoidalar **tartib bilan**, yuqoridan pastga qo'llanadi — `!` o'zi bekor qiladigan qoidadan keyin turishi shart.

## 3-blok. Tayyor shablonlar

Qoidalarni noldan yozish o'rniga real dasturchilar **shablonlar** oladi — har bir til uchun GitHubda bor. Asosiylarini baribir tanib olish lozim:

| Holat | Pattern |
| --- | --- |
| macOS axlati | `.DS_Store` |
| Node.js bog'liqliklari | `node_modules/` |
| Python baytkod/kesh | `__pycache__/`, `*.py[cod]` |
| Python virtual muhit | `venv/`, `.venv/` |
| Sirli muhit o'zgaruvchilari | `.env`, `.env.*` |
| Loglar | `*.log` |
| Muharrir/IDE papkalari | `.idea/`, `.vscode/`, `*.swp` |
| Build natijalari | `dist/`, `build/`, `out/`, `target/` |

**Tayyor shablon** [github.com/github/gitignore](https://github.com/github/gitignore)da yashaydi — masalan, `Node.gitignore` yoki `Python.gitignore`ni qidirib toping. Keraklisini o'z `.gitignore`ingizga ko'chiring.

### Muhim nuance

GitHub loyihalar repozitoriy yaratishda tegishli shablonni avtomatik qo'shadi: «New repository» formasida **Add .gitignore** ro'yxati bor. Yangi repozitoriy yaratishda foydalaning — natijani baribir tekshirish kerak.

## 4-blok. Bo'sh papkalar va `.gitkeep`

**Git tarkibni kuzatadi, papkalarni emas.** Bo'sh papkada commit yo'q — ichida fayllari bo'lmagan papka yaratib, `git status` bajarsangiz, u ko'rinmaydi. Masofaviy repozitoriy u haqida «bilmagan» bo'ladi.

Bo'sh papkani saqlash kerak bo'lsa (masalan, kelajakdagi loyiha uchun `images/`), ichiga zaplovk-fayl qo'ying:

```text
images/.gitkeep
```

`.gitkeep` — bo'sh zaplovk-fayl, umumqabul qilingan konventsiya (nomining o'zi aytadi: «bu papkani saqla»). Endi papkada tarkib bor — u kuzatiladi.

**Muqobil:** `.gitkeep` o'rniga ba'zilar bo'sh papkaga darhol real fayl qo'yadi — masalan, tavsifli `images/README.md`. Bu yanada foydali.

## 5-blok. Loyiha ildizi gigiyenasi

Toza repozitoriy ildiz papkadan boshlanadi. Standart minimal to'plam:

| Fayl/Papka | Maqsadi |
| --- | --- |
| `README.md` | Bu qanaqa loyiha, qanday ishga tushirish, havolalar |
| `LICENSE` | Kodni qanday shartlarda ishlatish mumkin |
| `.gitignore` | Repozitoriysa nima tushmaydi |
| `src/` yoki `css/`, `js/`... | Turlari bo'yicha joylangan manbalar (HTML kursidagidek) |
| `docs/` | Hujjatlar, agar ko'p bo'lsa |

### READMEda nima bor

- **Loyiha nomi** va u nima qilishi haqida bitta gap.
- **O'rnatish** — qanday ishga tushirish.
- **Foydalanish** — qisqa misol.
- **Lisenziya** va muallif (CC BY-NC-SA bo'yicha — materiallardan foydalansangiz, kurs muallifi eslati ladi).

**Qoida:** README'siz repozitoriy tashlandiq ko'rinadi; yaxshi README bilan — professional.

## 6-blok. Sirlar: hech qachon commit qilmaslik

Repozitoriysa qo'yish mumkin bo'lgan eng xavfli fayl — **tokenlar, parollar, API kalitlari** turgani. Nega bu halokatli:

- commit qilingan sir **tarixda abadiy qoladi** — o'chirsangiz ham, commitda saqlanib qoladi;
- repozitoriy ochiq bo'lishi mumkin — sir ommaviy bo'ladi;
- asboblar GitHubni skanerlab, **oqib chiqqan kalitlarni avtomatik topadi** — keyin provayder (GitHubning o'zi, AWS va h.k.) ularni bekor qilishi yoki xabar berishi mumkin.

### Sirlar bilan qanday to'g'ri ishlash

1. **Kodga hech qachon haqiqiy sir yozmang.** Uni muhit o'zgaruvchisiga yoki lokal `.env` fayliga qo'ying.
2. `.env`ni `.gitignore`ga **avval**, hali yaratmasdanoq qo'shing.
3. Haqiqiy qiymatsiz misol ilova qiling: `KEY=` placeholders bilan `.env.example` — uni commit qilish xavfsiz. Buning uchun `.gitignore`ga inkor qoidasini qo'shing (`!` bilan 2-blokda tanishgandik):

```gitignore
# .gitignore
.env
.env.*
!.env.example    # sirsiz misol xavfsiz commit qilinadi
```

```text
# .env.example — xavfsiz commit qilinadi
API_KEY=
DATABASE_URL=
```

Agar sir *allaqachon* commitingan bo'lsa — darhol **rotate** qiling (xizmat sozlamalarida yangisini chiqaring) va faqat keyin o'chiring. Faqat tarixni tozalash etarli emas.

## Mini-vazifa

«O'z mini-saytimizni yozamiz» o'quv loyihasi uchun `.gitignore`ni o'zingiz yarating:

1. `.DS_Store` va `.vscode/`ni ignore qiling.
2. `build/` papkasini ignore qiling.
3. Barcha `.log` fayllarini ignore qiling, lekin `important.log`ni saqlang.
4. `src/`ni **ignorean-mang**.

**Yechim:**

```gitignore
.DS_Store
.vscode/
build/
*.log
!important.log
```

---

## Dars xulosalari

Bugun siz quyidagilarni o'rgandingiz:

- **`.gitignore`** — «chamadonga solmaymiz» ro'yxati: Git nimalarni kuzatmaydi.
- Patternlar: izohlar (`#`), papkalar (`nom/`), `*`, `**`, inkor (`!`) tartibida.
- Node.js, Python, macOS va muharrirlar uchun tayyor shablonlar.
- Git **bo'sh papkalarni** ignore qiladi — `.gitkeep` zaplovkasi ularni repozitoriyda saqlaydi.
- Toza ildiz: README, LICENSE, `.gitignore`, saranjom papkalar.
- **Sirlar hech qachon commit qilinmaydi** — avval `.env` ignore qilinadi, oqib chiqqan kalit rotate qilinadi.

---

## Amaliy vazifa

«tidy-project» o'quv repozitoriysini yarating:

1. `git init` va min-vazifadan patternlar bilan `.gitignore` yozing.
2. `src/`, `images/` bo'sh papkalarini `.gitkeep` bilan va `README.md`, `.env.example`, `important.log`, `debug.log` fayllarini yarating.
3. `git status` bajaring va Git qaysi fayllarni ko'rishini, qaysilarini ignore qilishini tekshiring.
4. Munosib fayllarni commit qiling. `debug.log` va `.env` commitda yo'qligiga ishonch hosil qiling.
5. Inkor usulini sinab ko'ring: agar `.gitignore`da bo'lmasa, `!important.log` qo'shing va `git status`ni qayta tekshiring.
